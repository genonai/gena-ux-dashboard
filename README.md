# UX KPI 대시보드 (로컬)

Amplitude 데이터를 해석하고, UX 개선안과 그 효과를 기록하는 도구입니다.
내 Mac에서 작은 서버를 켜고 브라우저로 씁니다. 데이터는 이 폴더의 `data/`에 저장됩니다.

## 켜기

1. `start.command`를 더블클릭합니다. 서버가 켜지고 브라우저에서 http://localhost:4321 이 열립니다.
   - 처음 열 때 "확인되지 않은 개발자" 경고가 나오면, 파일을 오른쪽 클릭 → 열기를 누르세요.
   - 터미널에서 `npm start`로 켜도 됩니다.
2. 끌 때는 서버 창을 닫거나 `Ctrl+C`를 누릅니다.

필요한 것: Node.js 20.12 이상. 따로 설치할 패키지는 없습니다.

## AI 해석

API 키가 필요 없습니다. 이 Mac에 설치된 **Claude Code**(`claude` 명령)로 실행하며,
사용량은 로그인된 Claude 요금제 한도에서 차감됩니다.
"Claude Code 로그인이 필요합니다"라고 나오면 터미널에서 `claude`를 한 번 실행해 로그인하세요.

## Amplitude 자동 갱신 (선택)

**키 없이 쓰기 (기본):** Claude Code에 Amplitude 커넥터가 연결돼 있으면(`claude` 실행 → `/mcp` → amplitude 로그인)
API 키 없이 가져옵니다. 저장하지 않은 차트 주소(`…/chart/new/…`)도 됩니다. 차트 하나에 30초쯤 걸리고 Claude 요금제 사용량이 조금 듭니다
(모델은 `.env`의 `CLAUDE_FETCH_MODEL`, 기본 haiku).

**데이터 기간:** 자동 갱신 차트마다 기간(기본 최근 7일)을 고를 수 있고, "모든 차트 기간"으로 한 번에 바꿀 수 있습니다.
차트에 저장된 기간과 다르면 차트 정의의 기간만 바꿔 다시 계산합니다(커넥터로만 가능).

**AI 해석 일괄 실행:** 대시보드의 "AI 해석 모두 실행"을 누르면 지표마다 최신 저장본 중 해석이 없는 것을 서버가 차례로 해석합니다.
매주 자동 갱신 뒤에도 자동으로 이어서 돕니다(`.env`에 `AUTO_ANALYZE=off`로 끔, 동시 실행 수는 `ANALYZE_CONCURRENCY`, 기본 3).

**AI 해석 모아보기:** 상단 "AI 해석 모아보기" 탭에서 모든 지표의 최신 AI 해석을 한 화면(요약표 + 카테고리별 상세)으로 보고,
"전체 Markdown 내려받기"로 한 파일에 담을 수 있습니다.

**해석 정확도:** AI 해석에는 ① 자동 갱신 차트마다 적어 둔 지표 정의(`definition_text`: 분모·분자·인정 시간·주의사항), ② 팀 공통 맥락, ③ 같은 길이 직전 기간과의 비교와 통계 판정(의미 있는 변화/우연일 수 있음/표본 부족), ④ 표본 30명 미만 경고가 함께 들어갑니다. 해석에 나온 숫자 중 데이터에서 찾지 못한 것은 리포트에 "확인 필요한 수치"로 표시합니다. 수식 차트는 `series_labels`로 계열 이름을 바꿀 수 있습니다(예: `TOTALS(B)/TOTALS(A)` → 완료율).

**API 키로 쓰기 (참고):** API 키는 기간을 따로 정하지 않고 차트에 저장된 기간 그대로 가져올 때만 쓰입니다. 자동 갱신은 늘 "어제까지 N일"처럼 기간을 정해 가져오므로 위의 Claude Code 커넥터를 씁니다.

1. `.env.example`을 복사해 `.env`로 이름을 바꾸고 `AMPLITUDE_API_KEY`, `AMPLITUDE_SECRET_KEY`를 채웁니다.
   (Amplitude → Settings → Projects → 해당 프로젝트. EU 데이터센터면 `AMPLITUDE_REGION=eu`)
2. 서버를 다시 켭니다.
3. 대시보드 → 자동 갱신 차트 → **차트 추가**에 Amplitude에 *저장된* 차트 주소와 데이터 기간(일)을 넣습니다.
4. **지금 갱신**을 누르면 바로 가져오고, 서버가 켜져 있으면 매주 수요일 오전 10시에 자동으로 가져옵니다(수요일 보고용. `.env`의 `REFRESH_DAY`·`REFRESH_HOUR`로 바꿈).
   그 시각에 꺼져 있었다면 다음에 켤 때 한 번 가져옵니다.
   기간은 그 주 갱신 시각(수요일 10시)을 기준으로 한 번 정해서 모든 차트에 같이 씁니다. 같은 주에 다시 갱신해도 같은 기간(지난 수~화)이 돼서 저장본이 겹쳐 쌓이지 않습니다(`ANCHOR_WEEKLY=off`로 예전처럼 지금 기준). 실패한 차트는 60분 뒤부터 최대 3번 그 차트만 다시 받습니다.
   커넥터 로그인이 만료되면 첫 실패에서 멈추고, 로그인한 뒤 다음 시도 때 이어서 합니다.
   갱신이 실패했거나(로그인 만료 포함) 9일 넘게 돌지 않았으면 대시보드 맨 위에 빨간 배너로 알려 줍니다(원본 화면에서만, 보기 전용 사본에는 안 보임).
   서버가 꺼져 있을 때만 `npm run refresh`로 가져올 수 있습니다(서버가 켜져  있으면 안내하고 멈춥니다. 화면의 "모두 갱신"을 쓰세요).

## 설정(.env)과 Claude 사용량

차트 하나를 가져올 때마다 Claude Code 세션이 한 번 열립니다(저장 안 한 차트 약 $0.03~0.07). AI 해석도 지표마다 한 번입니다. 사용량을 줄이는 설정은 아래 표시한 것입니다.

| 옵션 | 기본값 | 내용 |
|---|---|---|
| `AUTO_REFRESH` | 켜짐 | 매주 자동 갱신. `off`로 끔 |
| `REFRESH_DAY` / `REFRESH_HOUR` | 3(수) / 10 | 자동 갱신 요일(0=일)·시각 |
| `ANCHOR_WEEKLY` | 켜짐 | 기간을 그 주 갱신 시각 기준으로 고정. `off`면 지금 기준 |
| `RETRY_MAX` / `RETRY_EVERY_MIN` | 3 / 60 | 실패한 차트만 다시 받는 횟수·간격(분). `RETRY_MAX=0`이면 재시도 없음 |
| `AUTO_ANALYZE` | 켜짐 | 갱신 뒤 새 저장본 AI 해석. `off`로 끔 |
| `SKIP_ANALYZE_BELOW` | 10 | 분모(첫 단계 사람 수)가 이 값 미만인 지표는 AI 해석·종합 진단에서 뺍니다(결론이 "표본 부족"뿐이라서). 카드에 문구만 보이고, 상세 화면에서 직접 해석할 수는 있습니다. 메인 KPI는 늘 해석. 0이면 끔 |
| `REUSE_ANALYSIS` | 켜짐 | 값이 거의 같으면 직전 해석을 이어 씀(사용량 절약). `off`로 끔 |
| `REUSE_PCT_POINTS` / `REUSE_REL` | 1 / 0.05 | "거의 같다"의 기준(비율 지표는 %p, 그 밖은 상대 비율) |
| `UXREPORT` | 끔 | 매주 종합 진단(가장 큼). 화면 버튼으로 필요할 때만 |
| `BACKFILL` | 끔 | 갱신 뒤 이전 기간 채우기(한 번에 최대 약 100회) |
| `PLATFORM_EVERY_DAYS` | 21 | 메인 KPI가 아닌 지표의 플랫폼별 수집 주기(일) |
| `DEF_TTL_DAYS` | 21 | 저장된 차트 정의를 다시 쓰는 기간(일) |
| `KEEP_SNAPSHOTS` | 26 | 차트마다 남기는 저장본 수(약 반년). 넘으면 오래된 것부터 지움(개선 트래커에 연결된 것은 보존). 0이면 안 지움 |
| `CLAUDE_MODEL` | opus | AI 해석 모델(`sonnet` 등) |
| `CLAUDE_EFFORT` | 비움 | 해석의 생각 수준 `low`/`medium`/`high`/`max`. 비우면 Claude Code 기본 |
| `CLAUDE_FETCH_MODEL` | haiku | 차트 정의·데이터 조회 모델 |
| `CLAUDE_COPY_MODEL` | sonnet | 기간을 바꿔 다시 계산할 때 정의를 옮기는 모델. `haiku`로 낮출 수 있음 |
| `CLAUDE_COPY_FALLBACK` | sonnet | 위 모델이 정의를 틀리게 옮기면 한 번 더 시도할 모델 |
| `CLAUDE_FETCH_EFFORT` | low | 차트 가져오기 세션의 생각 수준 |
| `ANALYZE_CONCURRENCY` | 3 | AI 해석 동시 실행 수(1~6) |
| `PUBLISH` / `PAGES_PROJECT` | 끔 / ux-kpi-dashboard | 클라우드 사본 자동 올리기·프로젝트 이름 |
| `APP_PASSWORD` | 없음 | 접속 비밀번호 |
| `PORT` / `HOST` | 4321 / 127.0.0.1 | 서버 주소 |

**주 단위 차트:** 집계 단위가 7일(주)인 차트는 Amplitude가 월~일 한 주를 한 칸으로 주고 덜 끝난 주는 뺍니다. 그래서 이런 차트는 기간을 처음부터 월~일 한 주로 맞춰 가져옵니다. 일 단위 차트(수~화)와 기간이 며칠 다르게 보이는 게 정상입니다.

**사용량 기록:** 매주 갱신이 끝나면 서버 창에 `[사용량] 가져오기 N회(haiku a·sonnet b) 약 $… · 해석 M회 … · 합계 약 $…` 한 줄이 나오고, 같은 내용이 `data/settings.json`의 `refresh.usageLine`에 남습니다. 다음 주와 비교해 사용량 변화를 보세요.

같은 포트로 서버를 두 번 켜면 두 번째는 안내만 하고 꺼집니다(서버 둘이 같은 파일에 쓰면 저장 내용이 서로 덮어써집니다).

## 폴더 구성

| 경로 | 내용 |
|---|---|
| `public/index.html` | 대시보드 화면 |
| `public/runtime.js` | 화면과 로컬 서버를 잇는 부분 (저장, AI, 파일 내려받기) |
| `server.mjs` | 로컬 서버 |
| `lib/` | 저장소, Claude Code 호출, Amplitude API, 자동 갱신 |
| `data/` | 저장된 분석, 트래커, 설정 (백업하려면 이 폴더를 복사) |
| `.env` | Amplitude 키 등 설정 (다른 사람과 공유하지 마세요) |

## 노트북이 꺼져 있어도 보기 (보기 전용 클라우드 사본)

지금 데이터를 담은 **보기 전용 사본**을 Cloudflare Pages에 올릴 수 있습니다(`npm run publish`, 또는 `PUBLISH=on`이면 매주 자동 갱신 뒤).
팀은 고정 주소(`https://ux-kpi-dashboard.pages.dev`)에서 `.env`의 `APP_PASSWORD`로 언제든 봅니다. 편집·갱신·AI 해석은 이 Mac의 원본에서 합니다.

처음 한 번:
1. Cloudflare 계정(무료)을 만들고, 터미널에서 `npx wrangler login`을 실행해 브라우저로 로그인합니다.
2. `npm run publish`로 처음 올립니다. 프로젝트 이름은 `.env`의 `PAGES_PROJECT`(기본 ux-kpi-dashboard)로 바꿀 수 있습니다.

기본은 자동으로 올리지 않습니다. 매주 자동 갱신 뒤에도 올리려면 `.env`에 `PUBLISH=on`을 넣으세요. 필요할 때는 `npm run publish`로 올립니다. 비밀번호를 바꾸면 다시 올려야 새 비밀번호가 적용됩니다.

## 외부에서 접속하게 공유하기 (재택 등)

1. `.env`에 `APP_PASSWORD=비밀번호`를 넣고 서버를 켭니다(`start.command`). 모든 접속에 비밀번호를 묻습니다(사용자 이름은 아무거나).
2. `share.command`를 더블클릭하면 `https://….trycloudflare.com` 주소가 나오고 클립보드에 복사됩니다. 주소와 비밀번호를 팀원에게 보냅니다.
3. 창을 닫으면 공유가 끝납니다. 주소는 열 때마다 바뀝니다. 이 Mac과 서버가 켜져 있어야 접속됩니다.

필요한 것: `brew install cloudflared`. 이 빠른 터널은 실시간 알림을 넘기지 못해서, 외부 접속 화면은 10초마다 새 내용을 다시 읽습니다.
접속한 사람이 갱신이나 AI 해석을 돌리면 이 Mac의 Claude 요금제 사용량이 쓰입니다.

## 팀원과 같이 쓰기

`.env`에 `HOST=0.0.0.0`을 넣으면 같은 네트워크의 팀원이 `http://내-Mac-IP:4321`로 접속할 수 있습니다.
`.env`에 `APP_PASSWORD`를 넣지 않으면 접속한 누구나 내용을 고칠 수 있으니, 비밀번호를 넣거나 믿을 수 있는 사내망에서만 쓰세요.
